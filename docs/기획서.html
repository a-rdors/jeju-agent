제주 같이나들이

이동약자와 함께하는 제주 나들이를, 공공데이터 근거로 준비해 주는 AI Agent

제주 AI·빅데이터 활용 AI Agent 개발 챌린지AI Agent 기획서2026.11
한 줄 요약. 휠체어·유모차·시니어와 함께 나들이를 준비하는 가족이 평소 말투로 조건을 말하면, Agent가 제주데이터허브의 무장애 여행 데이터를 조회해 조건에 맞는 장소를 고르고, 경사·계단·화장실 같은 근거와 가까운 약국·응급실·정류소, 데이터 기준일을 담은 인쇄용 코스표를 만들어 준다.

1. 구현 목표

분석 주제

제주데이터허브에는 제주특별자치도가 현장 조사한 무장애 여행 데이터가 장소별로 흩어져 있다. 공개 데이터 기준 50개 장소, 1,095개 지점의 위치 설명에 "오르막 시작 6도", "단차 9cm", "계단 8개, 휠체어 진입 어려움" 같은 구체적인 현장 정보가 들어 있다. 그러나 이 정보는 장소마다 다른 파일의 자유로운 문장으로 적혀 있어, 일반 도민이 "우리 가족이 갈 수 있는 곳"을 비교하기 어렵다.

AI를 활용한 분석 목표

  1. 문장을 비교 가능한 정보로: 지점별 설명 문장을 AI로 읽어 경사도, 계단, 단차, 노면, 장애인 화장실·주차 항목의 표로 바꾼다.
  2. 조건에 맞는 장소 선별: 사용자의 이동 유형과 조건에 맞춰 장소를 고르고, 왜 맞는지 근거 지점을 함께 제시한다.
  3. 오래된 정보 재확인: 2021년 조사 기준인 주변 식당·숙소를 2025년 음식점·숙박업 데이터와 대조해 영업 확인 여부를 표시한다.
  4. 비상 대비 정보 결합: 코스 근처 약국, 병·의원, 응급실, 버스 정류소를 함께 제공한다.

2. 서비스 제안

사용자와 사용 장면

구분사용자장면
주 사용자이동약자와 나들이를 준비하는 가족주말 나들이 전, 센터나 집에서 코스를 고르고 코스표를 인쇄·공유
2차 사용자복지 담당자, 돌봄 종사자이용자 외출 프로그램을 계획할 때 후보 장소와 주의 지점 확인

1차 대상 이동 유형은 휠체어(수동·전동), 유모차, 시니어다. 공개 데이터에 점자·음성 안내 정보가 없어 시각장애인용 안내는 이번 범위에서 제외한다.

사용 예시

"전동 휠체어 타는 아버지 모시고 서귀포 쪽 반나절 나들이. 경사 심한 곳 빼고, 장애인 화장실 있는 곳으로."

Agent는 조건을 정리하고, 부족하면 "출발 지역이 어디인가요?"처럼 되묻는다. 결과로 장소 2~3곳, 장소별 최대 경사와 주의 지점, 장애인 화장실 위치, 주변 식당 영업 확인 결과, 가까운 약국·응급실·정류소, 데이터 기준일과 출처를 담은 코스표를 보여 준다.

기능내용

편의성

  • IT 비전문가도 쓸 수 있도록 입력은 문장 한 줄 또는 버튼 선택 중 편한 방식으로 한다.
  • 결과는 한 장짜리 코스표로 정리해 인쇄하거나 휴대폰으로 가져갈 수 있다.
  • 모르는 정보는 추측하지 않고 "확인 안 됨, 방문 전 전화 확인 권장"과 전화번호를 함께 보여 준다.

분석 데이터 활용 방안

정제한 접근성 표는 Agent 밖에서도 쓸 수 있다. 장소별 최대 경사, 계단·단차 지점, 장애인 화장실 유무를 한 표로 묶어 제주빅데이터센터에서 무장애 관광 현황 분석이나 시설 개선 우선순위 검토 자료로 활용할 수 있다.

3. Agent 개발 구성

역할과 목표

Agent의 역할은 "근거를 보여 주는 나들이 준비 도우미"다. 목표는 사용자 조건에 맞는 장소를 데이터 근거로 고르고, 확인되지 않은 정보는 확인되지 않았다고 알려 주는 것이다.

Workflow

① 조건 파악이동 유형, 지역, 시간, 필수 조건 추출. 부족하면 되묻기
② 장소 검색접근성 표에서 조건에 맞는 후보 조회
③ 주변 확인약국·응급실·정류소 조회, 식당·숙소 영업 대조
④ 결과 검사모든 추천 근거가 실제 데이터에 있는지 확인
⑤ 코스표 작성근거·기준일·출처·한계를 담아 출력

AI 모델은 각 단계에서 필요한 도구를 스스로 골라 호출하고, 도구 결과를 보고 다음 행동을 정한다. 충분한 근거가 모이면 코스표를 작성한다.

공개 무장애 데이터와 음식점·상가·응급실 파일은 내려받아 확인했고, 약국·버스 정류소 API는 프로젝트 키로 호출을 확인했다. 병·의원, 관광 숙박업 API는 같은 형식으로 연동한다. 카카오 지도·로컬 API는 키 발급 후 연동할 예정이다.

수집·전처리 방법

  1. 수집: 허브 파일 다운로드와 프로젝트 키 기반 API 호출. API는 페이지 단위로 전체를 받아 저장해 두고 실행 중에는 필요할 때만 갱신한다.
  2. 정리: "오르막 시작"과 "오르막 시작점" 같은 표기 차이를 통일하고, "삭제" 표시 지점과 내용 없는 표시 문구("접근성정보 있음")를 제외한다.
  3. 구조화: 지점 설명 문장에서 경사도(도), 단차(cm), 계단 수, 노면, 화장실·주차 정보를 AI로 추출하고, 숫자는 원문에 실제로 있는 경우만 채택한다.
  4. 검수: 무작위 표본 지점을 사람이 원문과 대조해 추출 정확도를 측정하고 결과 설명자료에 기록한다.
  5. 좌표 연결: 주소만 있는 데이터는 상가 정보와 이름·주소로 연결하거나 카카오 로컬 API로 좌표를 구한다.
  6. 영업 대조: 2021년 주변시설을 2025년 음식점·숙박업 데이터와 상호명·주소로 대조한다.

경사 기준

경사 판단에는 임의 기준을 쓰지 않는다. 「장애인·노인·임산부 등의 편의증진 보장에 관한 법률 시행규칙」 별표 1의 접근로 기울기 기준(18분의 1 이하, 지형상 곤란한 경우 12분의 1까지 완화)을 각도로 바꿔 약 3.2°와 약 4.8°를 경계로 쓴다. 기준값은 국가법령정보센터 현행 원문으로 다시 확인해 확정한다.

이용조건

  • 제주데이터허브 이용약관과 데이터별 이용조건을 따르고, 결과물과 코스표에 데이터 출처와 기준일을 표기한다.
  • 대회 제공 데이터 목록 파일은 외부 저장소에 올리지 않는다.
  • API 키는 코드에 넣지 않고 환경변수(.env)로 관리하며 제출물에서 제외한다.
  • 개인정보가 포함된 데이터는 사용하지 않는다. 사용 데이터는 장소·시설 단위 공공 정보다.

  • 최소사양: 센터 Agent 운영 PC(Intel Core i7-8700 / GTX 1060 / RAM 32GB)에서 동작하도록 설계한다. AI 연산은 외부 API에서 처리하므로 PC에 GPU 부담이 없다. 실행은 Python 설치 후 실행 스크립트 하나로 한다.

6. 검증 방법과 한계

검증 방법

  • 추출 정확도: 무작위 지점 표본을 원문과 대조해 경사·계단·화장실 항목의 정확도를 측정한다.
  • 시나리오 테스트: 휠체어·유모차·시니어 조건의 질문 10개 이상을 만들고 추천 결과가 조건을 지키는지, 모든 근거가 원본 데이터에 있는지 확인한다.
  • 재현성: 같은 질문에 같은 후보가 나오도록 장소 선별과 경사 등급은 코드로 계산한다. 테스트 질문과 결과를 제출물에 포함한다.

한계

데이터 기준일. 무장애 현장 정보는 2021년 전후 조사 자료로, 현재 시설 상태와 다를 수 있다. 코스표에 기준일을 표시하고 방문 전 확인을 권장한다.
  • 주변 시설의 빈칸은 "불가"인지 "미조사"인지 구분할 수 없어 "확인 안 됨"으로 표시한다.
  • 상호가 바뀐 가게는 영업 대조에서 놓칠 수 있다.
  • 지도 서비스는 휠체어 기준 경로를 제공하지 않는다. 경로 접근성 판단은 무장애 조사 지점 정보에 근거한다.
  • 실제 이동약자 사용자 대상 테스트는 이번 범위에 포함하지 않는다.

선택 이유

  • 데이터 활용: 자유 문장을 비교 가능한 표로 바꾸는 실질적 처리 과정이 있다.
  • Agent 기술성: 장소 검색, 주변 확인, 영업 대조, 코스표 작성으로 도구를 여러 개 쓰는 흐름이 자연스럽다.
  • 창의성: 관광·버스·창업보다 다른 팀과 겹칠 가능성이 낮다고 판단했다. 다른 팀 주제는 알 수 없으므로 추정이다.
  • 신뢰성: 오래된 데이터를 최신 데이터로 다시 확인하는 구조가 들어 있다.
  • 일정: 데이터 확인과 기획이 끝난 상태라 9일 일정에 맞는다.

의료 접근 사각지대의 일부(가까운 약국·응급실 거리)는 이미 현재 기획의 비상 대비 기능에 들어가 있다.
