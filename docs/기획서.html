제주 같이나들이

이동약자와 함께하는 제주 나들이를, 공공데이터 근거로 준비해 주는 AI Agent

제주 AI·빅데이터 활용 AI Agent 개발 챌린지AI Agent 기획서2026.11
한 줄 요약. 휠체어·유모차·어르신·임산부와 함께 나들이를 준비하는 가족이 평소 말투로 조건을 말하면, Agent가 제주데이터허브와 한국관광공사의 무장애 여행 데이터를 조회해 조건에 맞는 장소를 고르고, 경사·계단·화장실 같은 근거와 가까운 약국·응급실·정류소, 데이터 기준일을 지도와 카드로 보여 준다.

1. 구현 목표

분석 주제

제주데이터허브에는 제주특별자치도가 현장 조사한 무장애 여행 데이터가 장소별로 흩어져 있다. 2021년 마을·해안길 조사 50곳과 2020년 관광지 조사 20곳, 모두 70개 장소 1,480개 지점의 위치 설명에 "오르막 시작 6도", "단차 9cm", "계단 8개, 휠체어 진입 어려움" 같은 구체적인 현장 정보가 들어 있다. 그러나 이 정보는 장소마다 다른 파일의 자유로운 문장으로 적혀 있어, 일반 도민이 "우리 가족이 갈 수 있는 곳"을 비교하기 어렵다.

AI를 활용한 분석 목표

  1. 문장을 비교 가능한 정보로: 지점별 설명 문장을 규칙(정규식)으로 읽어 경사도, 계단, 단차, 노면, 장애인 화장실·주차 항목의 표로 바꾼다. 같은 입력이면 항상 같은 표가 나오도록 이 단계에는 AI를 쓰지 않는다.
  2. 조건에 맞는 장소 선별: 사용자의 이동 유형과 조건에 맞춰 장소를 고르고, 왜 맞는지 근거 지점을 함께 제시한다.
  3. 오래된 정보 재확인: 2021년 조사 기준인 주변 식당·카페·숙소를 2025년 음식점 목록·상가 정보와 대조해 영업 확인 여부를 표시한다. 약국은 제주데이터허브 약국 정보의 영업 상태로 폐업한 곳을 뺀다.
  4. 비상 대비 정보 결합: 장소 근처 약국, 병·의원, 응급실, 장애인 화장실, 버스 정류소를 함께 제공한다.

공개 데이터에서 확인한 현장 정보 규모

70곳지점마다 현장 조사한 무장애 코스 장소(2021년 50곳, 2020년 20곳)
1,480개좌표와 설명이 있는 코스 지점
54곳코스 위에 경사도 숫자가 기록된 장소
834건조사 자료의 주변 식당·카페·숙소·관광지

정제 결과(data/processed) 기준, 2026.11.19 집계. 여기에 한국관광공사 무장애 여행 정보의 관광지·문화시설 177곳을 더해 모두 247곳을 추천한다. 관광공사 장소는 시설 입구·화장실·대여 기준 자료이고, 코스를 따라 경사를 잰 자료가 아니다.

2. 서비스 제안

사용자와 사용 장면

구분사용자장면
주 사용자이동약자와 나들이를 준비하는 가족주말 나들이 전, 센터나 집에서 PC·휴대폰으로 장소를 고르고 주의할 점과 근처 도움 시설을 확인
2차 사용자복지 담당자, 돌봄 종사자이용자 외출 프로그램을 계획할 때 후보 장소와 주의 지점 확인

대상 이동 유형은 휠체어(수동·전동), 유모차, 어르신, 임산부다. 임산부는 어르신과 같은 이동 기준에 가까운 산부인과와 '날음식 없는 식당' 조건을 더한다. 공개 데이터에 점자·음성 안내 정보가 없어 시각장애인용 안내는 이번 범위에서 제외한다.

사용 예시

"전동 휠체어 타는 아버지 모시고 서귀포 쪽 반나절 나들이. 경사 심한 곳 빼고, 장애인 화장실 있는 곳으로."

Agent는 조건을 정리하고, 부족하면 "출발 지역이 어디인가요?"처럼 되묻는다. 결과로 장소 2~3곳, 장소별 경사 단계와 주의 지점, 가까운 장애인 화장실, 근처 식당, 가까운 약국·응급실·정류소, 데이터 기준일과 출처를 지도와 오른쪽 대시보드에 보여 준다.

핵심 기능

기능내용
대화형 조건 입력평소 말투로 이동 유형, 지역, 시간, 필수 조건(화장실, 주차, 경사)을 입력. 빠진 조건은 되물음
근거 있는 장소 추천정제된 접근성 표로 후보를 거르고 추천 이유를 붙임. 판정 상자의 "근거 보기"를 누르면 판정에 쓴 공공데이터 조사 원문(코스 조사 지점 또는 관광공사 시설 항목)을 출처·기준일과 함께 그대로 보여 줌
경사 단계 표시경사 기록이 있는 장소끼리 최대 경사를 비교해 "완만한 편 / 보통 / 가파른 편"으로 표시. 법정 접근로 기울기(1/18)로는 대부분이 기준을 넘어 장소끼리 비교가 안 되므로 상대 단계를 쓴다
주변 정보 재확인2021년 조사 식당·카페·숙소를 2025년 음식점 목록·상가 정보와 대조해 "영업 확인 / 폐업 기록 / 확인 안 됨" 표시
비상 대비장소 근처 약국(폐업 제외), 병·의원, 응급실, 장애인 화장실, 버스 정류소와 직선거리
지도와 길안내추천 장소, 코스 지점과 주의 지점, 식당·병원을 카카오맵에 표시하고 카카오맵 길안내 링크 제공

편의성

  • IT 비전문가도 쓸 수 있도록 입력은 문장 한 줄 또는 버튼 선택 중 편한 방식으로 한다.
  • PC와 휴대폰에서 같은 주소(jeju-gachi.vercel.app)로 열 수 있고, 큰 글씨 모드를 제공한다.
  • 모르는 정보는 추측하지 않고 "확인 안 됨, 방문 전 전화 확인 권장"과 전화번호를 함께 보여 준다.

분석 데이터 활용 방안

정제한 접근성 표는 Agent 밖에서도 쓸 수 있다. 장소별 최대 경사, 계단·단차 지점, 장애인 화장실 유무를 한 표로 묶어 제주빅데이터센터에서 무장애 관광 현황 분석이나 시설 개선 우선순위 검토 자료로 활용할 수 있다.

3. Agent 개발 구성

역할과 목표

Agent의 역할은 "근거를 보여 주는 나들이 준비 도우미"다. 목표는 사용자 조건에 맞는 장소를 데이터 근거로 고르고, 확인되지 않은 정보는 확인되지 않았다고 알려 주는 것이다.

Workflow

① 조건 파악이동 유형, 지역, 시간, 필수 조건 추출. 부족하면 되묻기
② 장소 검색접근성 표에서 조건에 맞는 후보 조회
③ 주변 확인약국·병원·응급실·화장실·정류소, 근처 식당, 날씨 조회
④ 코드 보정모델이 빠뜨린 동네·이용자 유형·이미 본 장소·1층 우선 조건을 코드가 채움
⑤ 답변 작성정해진 형식의 짧은 답 + 지도·대시보드 카드(근거·기준일·출처)

AI 모델은 각 단계에서 필요한 도구를 스스로 골라 호출하고(한 질문에 최대 6번), 도구 결과를 보고 다음 행동을 정한다. 답변에 나온 장소·가게 이름이 도구 결과에 모두 있는지는 테스트 스크립트가 자동으로 점검한다.

판단 및 자율 수행 범위

Agent가 스스로 함

  • 조건 해석과 부족한 조건 되묻기
  • 도구 선택, 호출 순서, 후보 비교
  • 근거 지점을 골라 쉬운 말로 설명

Agent가 하지 않음

  • 예약, 결제, 전화 등 외부 행동
  • "안전하다"는 보장. 데이터 기준일과 한계를 항상 함께 표시
  • 판정 근거 원문을 바꿔 쓰기. 원문은 화면에 그대로 보여 주고 AI에게는 넘기지 않음
  • 데이터에 없는 시설 정보 추측

수집·전처리 방법

  1. 수집: 허브 공개 파일 다운로드(scripts/01), 프로젝트 키 기반 허브 OpenAPI 호출(scripts/07_hub_api.py), 관광공사 API·공중화장실 좌표(scripts/06). API는 페이지 단위로 전체를 받아 CSV로 저장해 두고, 실행 중에는 저장본을 쓴다.
  2. 정리: "오르막 시작"과 "오르막 시작점" 같은 표기 차이를 통일하고, "삭제" 표시 지점과 내용 없는 표시 문구("접근성정보 있음")를 제외한다.
  3. 구조화: 지점 설명 문장에서 경사도(도), 단차(cm), 계단 수, 노면, 화장실·주차 정보를 규칙(정규식)으로 추출하고, 숫자는 원문에 실제로 있는 경우만 채택한다(scripts/02).
  4. 검수: 무작위 표본 지점을 원문과 대조해 추출 정확도를 재고 docs/추출_검수기록.md에 기록한다. 고친 뒤에는 새 표본으로 다시 잰다.
  5. 좌표 연결: 주소만 있는 데이터는 상가 정보와 이름·주소로 연결하거나(응급실) 카카오 로컬 API로 좌표를 구한다(공중화장실).
  6. 영업 대조: 2021년 주변시설을 2025년 음식점 목록·상가 정보와 상호명·동네로 대조한다(영업 확인 315, 폐업 기록 44, 확인 안 됨 325). 약국은 허브 약국 정보와 이름·도로명으로 대조한다.

경사 기준

경사 판단에는 임의 기준을 쓰지 않는다. 「장애인·노인·임산부 등의 편의증진 보장에 관한 법률 시행규칙」 별표 1의 접근로 기울기 기준(18분의 1 이하, 지형상 곤란한 경우 12분의 1까지 완화)을 각도로 바꾸면 약 3.2°와 약 4.8°다. 정제 표에는 이 법 기준 등급을 함께 남겼지만, 경사 기록이 있는 54곳 중 53곳이 이 기준을 넘어 장소끼리 비교가 되지 않았다. 그래서 화면 판정에는 경사 기록이 있는 장소들의 최대 경사를 3등분한 상대 단계(완만한 편 / 보통 / 가파른 편)를 쓴다. 상대 단계는 "갈 수 있다"는 보장이 아니라 장소끼리 비교하기 위한 표시다.

이용조건

  • 제주데이터허브 이용약관과 데이터별 이용조건을 따르고, 화면 카드에 데이터 출처와 기준일을 표기한다.
  • 대회 제공 데이터 목록 파일은 외부 저장소에 올리지 않는다.
  • API 키는 코드에 넣지 않고 환경변수(.env)로 관리하며 제출물에서 제외한다.
  • 개인정보가 포함된 데이터는 사용하지 않는다. 사용 데이터는 장소·시설 단위 공공 정보다.

센터 실행환경과 외부 서비스 의존성

  • 최소사양: 센터 Agent 운영 PC(Intel Core i7-8700 / GTX 1060 / RAM 32GB)에서 동작하도록 설계한다. AI 연산은 외부 API에서 처리하므로 PC에 GPU 부담이 없다. 브라우저로 배포 주소(jeju-gachi.vercel.app)를 열면 설치 없이 쓸 수 있다. PC에서 직접 돌릴 때는 Python 3.11 이상과 Node.js 20 이상을 설치하고 API 서버와 웹 화면을 각각 실행한다(README 1장).
  • 외부 의존성: 실행 중에는 OpenAI API, 카카오 지도·로컬 API, Open-Meteo를 쓴다. 제주데이터허브 OpenAPI와 관광공사 API는 데이터를 다시 받을 때만 쓰고, 평소에는 저장해 둔 CSV를 읽는다. 모두 인터넷 연결이 필요하고, Open-Meteo를 뺀 나머지는 각 서비스의 키가 필요하다.
  • AI를 쓸 수 없을 때: OpenAI 키가 없거나 연결이 안 되면 버튼·단어 기반 기본 모드로 전환해, 미리 저장한 데이터로 장소를 추천한다.

6. 검증 방법과 한계

검증 방법

  • 추출 정확도: 무작위 지점 표본을 원문과 대조해 경사·계단·화장실 항목의 정확도를 잰다. 2021년 조사 50곳은 3회 측정해 93.3~96.7%(docs/추출_검수기록.md).
  • 시나리오 테스트: 튜닝·회귀 19개(scripts/04), 확인용 8개(scripts/05), 폭넓은 질문 46개(scripts/07_broad_test.py). 필요한 도구를 썼는지, 사용자 조건을 지켰는지, 답변의 장소·가게 이름이 모두 도구 결과에 있는지, 답변 형식과 금지 표현을 자동으로 채점한다.
  • 재현성: 같은 질문에 같은 후보가 나오도록 장소 선별과 경사 단계는 코드로 계산한다. 테스트 질문과 결과(docs/*_테스트.md)를 제출물에 포함한다.

한계

데이터 기준일. 무장애 현장 정보는 2020~2021년 조사 자료로, 현재 시설 상태와 다를 수 있다. 화면 카드에 기준일을 표시하고 방문 전 확인을 권장한다.
  • 관광공사 장소 177곳은 시설 입구·편의시설 기준 자료이고, 코스를 따라 경사를 잰 자료가 아니다.
  • 병원·약국·정류소 거리는 모두 직선거리다. 정류소의 저상버스 운행·노선은 확인하지 않는다. 장소 17곳은 1km 안에 정류소가 없다.
  • 약국 영업 상태는 이름·도로명이 맞는 기록이 있을 때만 붙는다(317곳 중 14곳은 확인 안 됨).
  • 주변 시설의 빈칸은 "불가"인지 "미조사"인지 구분할 수 없어 "확인 안 됨"으로 표시한다.
  • 상호가 바뀐 가게는 영업 대조에서 놓칠 수 있다.
  • 지도 서비스는 휠체어 기준 경로를 제공하지 않는다. 경로 접근성 판단은 무장애 조사 지점 정보에 근거한다.
  • 실제 이동약자 사용자 대상 테스트는 이번 범위에 포함하지 않는다.
