모델: OpenAI gpt-5.4-mini. 스크립트: `scripts/04_scenario_test.py`, `scripts/05_holdout_test.py`.

### 확인용 첫 실행에서 드러난 약점과 수정
- "엄마가 보행기 쓰시는데", "애기 데리고": 이동 유형 단서 단어(보행기, 애기)를 몰라 불필요하게 되물음 → 단서 단어 확장, 짧고 막연한 질문일 때만 코드가 되묻기
- "사려니숲 갈 수 있어?": 데이터 이름이 "사려니숲길-무장애나눔길"이라 못 찾음 → 이름 일부로 장소 찾기(`match_place`)

### 사용자 체험 중 발견해 고친 것
- "서귀포흑돈 근처 카페": 가게 이름을 근처 기준으로 못 찾음 → 가게 이름·동네·장소 순서로 기준 위치 찾기, 못 찾으면 솔직히 알림
- "할머니가 이가 안 좋으셔서": 식사 불편을 다루지 못함 → 식사 조건 6가지 추가, 식당 대상을 제주 전체 1만 9천 곳으로 확대
- "횟집은 글로만 나오고 카페만 카드로 나와": 한 질문의 여러 결과 중 마지막만 화면에 표시 → 한 질문의 결과를 모두 카드로, 약국·화장실 질문도 카드로
- "2층 카페는 휠체어로 못 가잖아": 층 정보 없음 → 음식점 인허가 주소의 층 표기를 연결(8,590곳), 거동 불편 시 1층 우선

### 튜닝 중 수정한 것
- 이동 유형을 코드가 먼저 감지(불필요한 되묻기 방지)
- 직전 추천 장소를 Agent에 전달("거기 근처 약국")
- 날짜·날씨 단어가 있으면 코드가 먼저 날씨 조회
- 사용자가 말한 동네를 모델이 빠뜨리면 코드가 채움, 거리 반영 강화, 시 단위 지역은 그 시 안에서만


## 3. 폭넓은 질문 테스트 (`scripts/07_broad_test.py`, 46개)

사용자가 실제로 입력할 만한 질문을 분류별로 모아 동작과 **답변 형식**을 함께 점검한다.
분류: 장소(이동 유형 5종) · 특정 장소 확인 · 식당(식사 조건 7종) · 병원·화장실 · 날씨 · 반나절 일정 · 여러 날 · 이어지는 질문 · 막연한 질문 · 범위 밖(제주 밖·숙소·맛 순위·의학 판단·예약) · 줄임말·오타.
점검: 오류 없음, 필요한 도구, 형식(분류별 고정 형식, 이모지·제목·목록·인사말 없음, 1순위 하나만), 근거(지어낸 이름 없음), 금지 표현.

| 회차 | 통과 | 주요 문제 → 수정 |
|---|---|---|
| 1 | 24/46 | 장소·식당을 여러 개 나열, '확인할 점' 대신 '조심할 점', 제주 밖 요청에 제주 장소 추천, 해산물 알레르기 + 해산물 종류 충돌로 결과 0, 일정인데 장소 형식, 119 누락 / 채점 오류(코드가 계산한 '비 오면' 대안·업종 이름을 지어낸 이름으로 판정) → 형식 규칙 강화, 충돌 방지, 채점 수정 |
| 2 | 41/46 | '조심할 점' 라벨 누락, 일정 형식 무시 → 일정 답변은 코드가 직접 작성, 라벨은 코드가 통일 |
| 3 | 43/46 | 식당 라벨, 제주 밖 요청 → 제주 밖이면 AI를 부르지 않고 고정 답변 |
| 4 | 44/46 | 식당 질문을 장소 질문으로 처리(AI 판단이 그때그때 다름) → 식당 단어가 있으면 식당 질문으로 명시, 식당 최소 3곳, 라벨 누락 시 데이터로 채움 |
| 5 | 45/46 | 남은 1건은 거절문의 '1위는 알려드릴 수 없어요'를 금지 표현으로 잡은 채점 오류 → 범위 밖 답변은 금지 표현 검사 제외, 해당 질문 재확인 통과 |

답변 형식을 지키는 방법: 시스템 프롬프트의 형식 규칙 + 코드 보정(`agent.normalize_answer`: 일정 답변 직접 작성, '다만…'→'조심할 점:', 식당 '확인할 점:' 통일·보충, 장소 '조심할 점:' 보충, 병원·화장실 119 안내).
같은 질문에도 AI 판단이 달라질 수 있어, 형식처럼 반드시 지켜야 하는 것은 코드로 고정했다.
