# 제주 같이나들이

> 일반 여행 앱은 "어디 갈까"를 묻고, 같이나들이는 "우리 가족이 갈 수 있을까, 뭘 조심할까"에 답합니다.

휠체어·유모차·어르신과 함께하는 제주 나들이를 공공데이터 근거로 도와주는 AI Agent.
제주 AI·빅데이터 활용 AI Agent 개발 챌린지 출품작.

## 할 수 있는 일

| 기능 | 내용 |
|---|---|
| 나들이 장소 추천 | 무장애 조사 70곳 중 이동 유형(휠체어·전동 휠체어·유모차·어르신)과 동네·분위기·화장실 조건에 맞는 곳 |
| 판정 한 줄 | 갈 만해요 / 동행인 도움이 있으면 갈 만해요 / 확인이 더 필요해요 |
| 확인한 것·못 한 것 | 경사, 계단, 턱, 장애인 화장실, 장애인 주차, 쉼터. 확인 안 된 항목은 그대로 "확인 안 됨" |
| 코스 따라가기 | "출발 후 약 130m 오르막" 같은 주의 지점, 화장실·쉼터 위치, 지도 |
| 식당·카페 | 제주 전체 약 1만 9천 곳. 휠체어 진입 확인 가게는 배지(휠체어 가족이면 앞으로) |
| 식사 조건 | 씹기 편한 음식, 속 편한 음식, 맵지 않은 음식, 해산물 알레르기, 싱겁게, 아이와 식사 |
| 근처 기준 | 나들이 장소, 가게 이름(예: "서귀포흑돈 근처 카페"), 동네, 현재 위치 |
| 날씨 판단 | 비 예보면 실내 제안, 비 온 뒤 미끄러운 길, 해안 강풍 주의 |
| 의료 | 가까운 약국·병의원·응급실 |
| 전화 확인 질문지 | 이동 유형·식사 조건별로 가게에 물어볼 질문 |
| 다른 곳 보기 | 이미 보여준 장소는 빼고 다시 추천 |

## 빠른 실행

```powershell
# 1. 가상환경과 라이브러리
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt

# 2. 키 파일 만들기: 프로젝트 폴더에 .env 파일을 만들고 아래를 넣는다
#    OPENAI_API_KEY=sk-...          (Agent 대화. 없으면 버튼 기반 기본 모드로 동작)
#    JEJU_PROJECT_KEY=...           (제주데이터허브 API. 현재 화면 실행에는 필요 없음)
#    KAKAO_JS_KEY=...               (카카오맵. 없으면 기본 지도. 카카오 개발자 앱에 Web 플랫폼 http://localhost:8501 등록, 카카오맵 사용 설정 ON)

# 3. 실행 (내 컴퓨터에서만 열림)
.venv\Scripts\streamlit run app/main.py --server.address localhost
```

브라우저에서 http://localhost:8501 을 연다. `.env`는 절대 GitHub에 올리지 않는다(`.gitignore`로 막혀 있음).

## 폴더 구조

| 경로 | 내용 |
|---|---|
| `app/main.py` | 화면(Streamlit). **화면 작업은 이 파일만** 바꾸면 된다 |
| `app/map_view.py` | 지도: 카카오맵 그리기, 키가 없으면 기본 지도 |
| `app/agent.py` | Agent: OpenAI 함수 호출 반복, 시스템 프롬프트, 되묻기·날씨·위치·근처 기준 처리 |
| `app/tools.py` | 도구: 장소 추천·판정, 코스 상세, 의료, 식당·식사 조건, 날씨, 전화 질문지. 모든 판단은 코드로 계산 |
| `.streamlit/config.toml` | 테마(색·글꼴·글자 크기) |
| `scripts/01~03` | 데이터 받기 → 문장을 접근성 표로 → 보조 표(동네·의료·영업 확인·식당) |
| `scripts/04~05` | 시나리오 테스트(튜닝·회귀 14개, 확인용 8개) |
| `data/raw` | 원본(제주데이터허브 무장애여행 정보, 상가·음식점·응급실) |
| `data/processed` | 정제 결과(Agent가 읽는 표) |
| `docs/` | 기획서, UX 흐름 설계, 검수·테스트 기록 |

다시 만들기:

```powershell
.venv\Scripts\python scripts/01_download_mujangae.py   # 공개 무장애 데이터 150개 파일
.venv\Scripts\python scripts/02_build_access_table.py  # 문장 → 접근성 표 (2020 관광지 20곳은 data/raw/mujangae_extra)
.venv\Scripts\python scripts/03_build_support.py       # 동네·의료·영업 확인·식당 표
```

## 테스트

```powershell
.venv\Scripts\python scripts/04_scenario_test.py   # 튜닝·회귀용 14개 → docs/시나리오_테스트.md
.venv\Scripts\python scripts/05_holdout_test.py    # 확인용 8개 → docs/시나리오_확인테스트.md
```

채점: 필요한 도구를 불렀나, 사용자 조건을 지켰나, 답변의 장소·가게 이름이 모두 도구 결과에 있나(지어내지 않았나).
기능을 고친 뒤에는 두 테스트를 모두 돌려 기존 동작이 깨지지 않았는지 확인한다. 경과는 `docs/테스트_기록.md`.

## 화면 작업하는 사람에게

- 결과 화면 순서, UX 원칙(근거 포함), 쓸 수 있는 데이터 필드: `docs/UX_흐름_설계.md`
- 현재 위치: 지도에서 위치 권한을 받으면 `st.session_state.location = (위도, 경도)`만 넣으면 Agent가 "내 근처" 기준으로 찾는다
- 지도 표시용 좌표: `tools.get_place_detail(place)["all_points"]`
- 길안내: `tools.kakao_route_link(이름, 위도, 경도)` (키 불필요)

## 한계

- 무장애 현장 정보는 2020~2021년 조사 자료라 현재와 다를 수 있다
- 식당 메뉴 자료가 없어 식사 조건은 업종·가게 이름으로 추정한다. 의학적 판단이 아니며 가게에 확인이 필요하다
- 상가 자료에는 전화번호가 없다(휠체어 진입 확인 가게 일부만 있음)
- 지도 서비스는 휠체어 기준 경로를 제공하지 않는다. 접근성 판단은 조사 지점 기준이다
- 날씨·판정·식사 조건 기준값은 설계 가정이다
