# 제주 같이나들이

> 일반 여행 앱은 "어디 갈까"를 묻고, 같이나들이는 "우리 가족이 갈 수 있을까, 뭘 조심할까"에 답합니다.

휠체어·유모차·어르신·임산부와 함께하는 제주 나들이를 공공데이터 근거로 도와주는 AI Agent.
제주 AI·빅데이터 활용 AI Agent 개발 챌린지 출품작.

---

## 1. 빠른 실행

필요한 프로그램: Python 3.11 이상, Node.js 20 이상.

```powershell
# 1) 가상환경과 라이브러리(API 서버)
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt

# 웹 화면 라이브러리(처음 한 번)
cd web; npm install; cd ..

# 2) 키 파일: 프로젝트 폴더에 .env 파일을 만들고 아래를 넣는다(값은 각자 발급)
#    OPENAI_API_KEY=sk-...     Agent 대화(없으면 버튼 기반 기본 모드로 동작)
#    KAKAO_JS_KEY=...          카카오맵(없으면 기본 지도. 카카오 개발자 앱 > 플랫폼 Web에 http://localhost:3000 등록, 카카오맵 사용 설정 ON)
#    KAKAO_REST_KEY=...        카카오 REST API(식당 전화번호. 없으면 전화번호만 빠짐)
#    TOUR_API_KEY=...          공공데이터포털 한국관광공사 무장애 여행 정보(데이터를 다시 받을 때만)
#    JEJU_PROJECT_KEY=...      제주데이터허브 프로젝트 키(현재 화면 실행에는 필요 없음)

# 3) 실행: 터미널 두 개
.venv\Scripts\python -m uvicorn server.api:app --port 8000   # 터미널 1: API 서버(추천·AI)
cd web; npm run dev                                        # 터미널 2: 웹 화면
```

브라우저에서 http://localhost:3000 을 연다(127.0.0.1 말고 localhost로). 웹 화면(3000)이 API 서버(8000)를 불러 쓴다. `.env`는 절대 GitHub에 올리지 않는다(`.gitignore`로 막혀 있음).

## 2. 서비스 원칙

1. **"갈 수 있을까"에 답한다.** 모든 결과에 접근성 판단(경사·턱·계단·화장실·주차·층)을 붙인다. 근거 없는 추천은 하지 않는다.
2. **사용자가 가장 편하게.** 숫자를 묻지 않는다. 평소 말("아빠가 휠체어 타셔")을 Agent가 해석하고, 꼭 필요할 때만 버튼으로 한 번 되묻는다.
3. **모르면 모른다고.** 확인 안 된 정보는 "확인 안 됨"으로 표시하고 전화로 물어볼 질문을 준다. "안전해요" 같은 보장은 하지 않는다.
4. **판단은 코드, 설명은 AI.** 순위·거리·판정은 코드가 계산(같은 질문엔 같은 결과). AI는 말을 해석하고 도구를 고르고 쉽게 설명한다.
5. **답변 형식 고정.** 답변 종류마다 같은 틀(아래 4장). 자세한 내용은 화면 카드가 보여준다.

## 3. 기능 전체

### 3-1. 이용자 유형
| 유형 | 판단 기준 | 식당 |
|---|---|---|
| 수동 휠체어 | 경사에 가장 민감, 계단·턱(10cm 이상) 주의 | 1층 우선, 휠체어 진입 확인 가게 우선 |
| 전동 휠체어 | 경사 덜 민감, 계단·턱 주의 | 1층 우선, 휠체어 진입 확인 가게 우선 |
| 유모차 | 경사·계단·노면, 수유실·유모차 대여 가산 | 1층 우선 |
| 어르신 | 경사·계단, 쉴 곳 적은 긴 코스 주의 | 1층 우선 |
| 임산부 | 어르신과 같은 이동 기준, 근처 산부인과 함께 안내 | 1층 우선, '날음식 없는 식당' 조건 |

이용자 유형은 첫 화면 버튼이나 말 속 단서(휠체어, 유모차, 애기, 할머니, 보행기, 임신, 만삭 등)로 정해진다.

### 3-2. 나들이 장소 추천 — `tools.recommend_places`
- 대상 247곳: 제주도 코스 조사 70곳(경사·턱을 지점마다 잰 자료) + 한국관광공사 무장애 시설 177곳(입구·화장실·대여 자료)
- 조건: 동네(애월·중문·서귀포 등 417개 이름), 분위기(바다·마을·자연·숲·역사·문화·실내·시장), 화장실 필요, 짧게(30분), 현재 위치
- 판정 한 줄(`access_summary`): **갈 만해요 / 동행인 도움이 있으면 갈 만해요 / 확인이 더 필요해요**
  - 코스 장소: 경사(70곳 상대 비교 3단계 + 법정 접근로 기준 참고), 계단, 턱
  - 시설 장소: 출입 경로(턱 없음·경사로), 장애인 화장실
- 확인표(`checks`): 항목마다 "확인됨 / 확인 안 됨"
- 추천 이유, 조심할 점, 비 오면 대신 갈 실내 장소(1순위 장소)
- 사진·소개(관광공사 169·177곳), 전화번호(카카오 155곳), 홈페이지, 장애인 주차구역 좌표 길안내(29곳)
- "다른 곳"이라고 하면 이미 보여준 장소를 빼고 다시 추천

### 3-3. 장소 상세 — `tools.get_place_detail`
- 코스 장소: 출발점부터 주의 지점 순서("출발 후 약 130m · 오르막 · 경사 약 8도"), 지도용 좌표
- 시설 장소: 출입 경로, 휠체어·유모차 대여, 수유실, 엘리베이터
- 가까운 장애인 화장실(공중화장실 자료, 2km 이내)
- 이름 일부로도 찾음("사려니숲" → 사려니숲길-무장애나눔길)

### 3-4. 식당·카페 — `tools.search_food`
- 대상: 제주 전체 19,316곳(2025 상가 자료)
- 종류: 해산물, 흑돼지·고기, 국수, 한식·백반, 카페, 분식
- 식사 조건(`diet_needs`, 업종·가게 이름으로 추정, 의학적 판단 아님)
  | 조건 | 쓰는 경우 |
  |---|---|
  | soft 씹기 편한 음식 | 이가 안 좋다, 틀니 |
  | gentle 속 편한 음식 | 소화가 어렵다 |
  | mild 맵지 않은 음식 | 매운 걸 못 먹는다 |
  | no_seafood 해산물 없는 식당 | 해산물 알레르기 |
  | low_salt 싱겁게 부탁하기 좋은 곳 | 짜게 먹으면 안 된다 |
  | kids 아이와 먹기 좋은 곳 | 아이 동반 |
  | no_raw 날음식 없는 식당 | 임신 중 등 날음식·술을 피하고 싶을 때 |
- 배지: 층(1층 / 2층·엘리베이터 확인 필요 / 층 정보 없음, 8,590곳), 휠체어 진입 확인(2021 조사 74곳 + 관광공사 음식점), 아기 의자
- 거동이 불편한 유형이면 1층 우선, 2층·지하는 뒤로
- 전화번호·카카오맵 링크(카카오, 실행 중 조회)
- 근처 기준: 나들이 장소, 가게 이름("서귀포흑돈 근처 카페"), 동네, 현재 위치. 기준을 못 찾으면 솔직히 알림

### 3-5. 병원·약국·화장실 — `tools.find_nearby_help`
- 가까운 약국 2곳, 병·의원 2곳(치과·성형 등 제외), 응급실 1곳, 장애인 화장실 2곳, 기저귀 교환대 1곳
- 임산부면 가까운 산부인과 추가
- 응급 상황은 119 안내

### 3-6. 날씨 — `tools.get_weather`
- Open-Meteo 7일 예보. "오늘·내일·주말·요일"을 말하면 코드가 먼저 조회
- 접근성 관점 주의만: 비 예보 → 실내 제안, 비 온 뒤 잔디·흙·데크 미끄럼, 해안 강풍(9m/s 이상)

### 3-7. 반나절 일정 — `tools.plan_outing`
- "일정·코스·반나절·하루·동선"을 말할 때만: 장소 → 근처 식당(식사 조건 반영) → (원하면) 카페
- 근처에 식당이 있는 장소를 우선, 장소마다 비 오면 대신 갈 실내 장소
- 결과 카드의 작은 "+ 일정"으로 직접 담을 수도 있음. 일정 칸은 담았을 때만 나타남
- **일정표 내려받기**(`itinerary_html`): 들르는 순서·거리, 장소별 확인표, 가까운 장애인 화장실, 급할 때 연락처, 전화로 확인할 것 → 인쇄·PDF 저장
- 여러 날(1박 2일 등) 시간표는 만들지 않는다(여행 기간이 제각각이라 주관적). 첫 나들이만 제안하고 "+ 일정"으로 모으도록 안내

### 3-8. 전화 확인 질문지 — `tools.call_questions`
이용자 유형 + 식사 조건별로 가게에 물어볼 질문. 예: "몇 층인가요? 엘리베이터가 있나요?", "음식을 잘게 잘라 주실 수 있나요?"

### 3-9. 화면 — `web/`(Next.js) + `server/api.py`(FastAPI)
- 화면 전체에 카카오맵(제주도 안에서만 이동), 오른쪽에 대시보드(한눈에·코스·식당·병원·약국·질문지), 오른쪽 아래 돌하르방 대화창
- 대화 답에 나온 장소는 단추로, 지도 표식을 누르면 대시보드도 그 장소로 이동
- 결과 순서 고정: 추천 장소 → 식당·카페 → 병원·약국·화장실 → 오늘 일정
- 웹은 화면만 그리고 판단·AI는 모두 API 서버가 `app/tools.py`, `app/agent.py`를 불러 처리(각 폴더 README)
- 현재 위치: API `/api/chat`의 `location: [위도, 경도]`를 보내면 "내 근처" 기준

### 3-10. AI 없이 동작(기본 모드) — `agent.rule_mode`
OpenAI 키가 없거나 연결이 안 되면 버튼·단어 기반으로 장소를 추천한다(센터 PC 인터넷 제한 대비).

## 4. 답변 형식(시스템 프롬프트 `agent.SYSTEM`의 4번)

| 종류 | 형식 |
|---|---|
| 장소 | `**장소** — 판정` / 이유 한 문장 / `조심할 점:` 한 문장 / (있을 때만) `비 오면:` 대안 |
| 식당 | `**가게** — 업종 · 층` / `추천 이유(추정):` / `확인할 점:` (종류마다 반복) |
| 병원·약국·화장실 | 가까운 곳과 거리 / `응급 상황에는 119에 먼저 연락하세요.` |
| 일정 | `**A → B → C**` / 고른 이유 / `일정표를 내려받을 수 있어요.` |
| 되묻기 | 버튼 질문 한 줄 |
| 범위 밖 | 못 하는 이유 한 줄 + 대신 할 수 있는 것 한 줄(제주 밖, 숙소, 맛 순위, 의학 판단, 예약) |

인사말·이모지·제목·목록 기호 없이 최대 4줄(식당 두 종류면 반복). 형식은 `scripts/07_broad_test.py`가 자동 점검한다.

## 5. Agent 구조 — `app/agent.py`

```
사용자 말
 ├─ 코드가 먼저: 이용자 유형 단서 감지, 가게·장소·동네 이름 인식, 날짜·날씨 단어면 날씨 조회,
 │              단서 없는 짧은 질문이면 버튼으로 되묻기, 여러 날 요청이면 규칙 추가
 ├─ OpenAI(gpt-5.4-mini) 함수 호출 반복(최대 6회)
 │    도구: recommend_places, get_place_detail, find_nearby_help, search_food, get_weather, plan_outing, ask_user
 ├─ 코드가 보정: 모델이 빠뜨린 동네·가게 기준·이미 본 장소·1층 우선·이용자 유형 채우기
 └─ 짧은 답변(형식 고정) + 화면 카드(도구 결과)
```

## 9-1. 배포(Vercel)

같은 저장소로 Vercel 프로젝트 2개를 만든다. GitHub `main`에 push하면 둘 다 자동으로 다시 배포된다.

| 프로젝트 | Root Directory | 하는 일 | 환경 변수 |
|---|---|---|---|
| 서버(예: `jeju-gachi-api`) | 저장소 맨 위(비워 둠) | `api/index.py` → `server/api.py`(FastAPI) | `OPENAI_API_KEY`, `KAKAO_REST_KEY`, `KAKAO_JS_KEY` (선택: `OPENAI_MODEL`, `CHAT_LIMIT_PER_10MIN`, `CHAT_LIMIT_PER_HOUR`) |
| 화면(예: `jeju-gachi`) | `web` | Next.js 화면. `/api/...` 요청을 서버로 넘김 | `API_ORIGIN` = 서버 주소(예: `https://jeju-gachi-api.vercel.app`) |

순서
1. 서버 프로젝트를 먼저 배포하고 주소를 확인한다(`/api/config`가 열리면 정상).
2. 화면 프로젝트에 `API_ORIGIN`을 넣고 배포한다. `API_ORIGIN`은 빌드할 때 읽으므로, 바꾸면 Redeploy가 필요하다.
3. 카카오 개발자 앱(JavaScript 키 발급한 앱)의 사이트 도메인에 화면 주소(`https://...vercel.app`)를 추가한다.

설정 파일: `vercel.json`(서버: 함수 최대 60초, web·docs·scripts·data/raw 제외), `api/index.py`(입구).
AI 호출 제한: 한 사용자 10분 30회, 서버 전체 1시간 600회. 넘으면 오류 대신 AI 없는 기본 모드로 답한다. 질문은 500자, 대화는 최근 16개까지만 AI에 넘긴다.
심사 기간에는 `main`에 바로 push하지 않는다(사이트가 바로 바뀜). 문제가 생기면 Vercel의 Instant Rollback으로 이전 배포로 되돌린다.

## 10. 한계와 향후 계획

**한계**
- 무장애 현장 정보는 2020~2021년 조사 자료라 현재와 다를 수 있다(코스 장소)
- 관광공사 장소는 시설 입구·편의시설 기준이고, 코스를 따라 경사를 잰 자료가 아니다
- 식당 메뉴·입식 테이블(좌식 여부)·휠체어 거치 공간·엘리베이터 자료가 없다. 식사 조건은 업종·이름으로 추정하고 전화 질문으로 보완한다
- 지도 서비스가 휠체어 기준 경로를 주지 않는다. 이동시간은 계산하지 않는다
- 판정·식사 조건·날씨 기준값은 설계 가정이다

**향후 계획**
- 브라우저 현재 위치를 "내 근처" 기준으로 자동 사용(API는 이미 `location`을 받음)
- 저상버스 실시간 도착, 휠체어 대여 수량 실시간 확인
- 식당 입식 테이블·엘리베이터 정보: 허가받은 리뷰·제휴 데이터 또는 센터 현장 조사
- 이용자 제보로 오래된 무장애 정보 갱신, 어르신용 큰 글씨 일정표·음성 안내
