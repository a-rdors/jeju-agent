# 결과 설명자료 — 제주 같이나들이

이동약자와 함께하는 제주 나들이를 공공데이터 근거로 준비해 주는 AI Agent

- 바로 써보기: **https://jeju-gachi.vercel.app** (PC·휴대폰 같은 주소, 설치 없음)
- 실행 방법: `README.md` 1장 · 사용법: `docs/사용자_매뉴얼.md` · 데이터: `docs/데이터_활용_명세.md`

---

## 1. 문제 정의

**누가 무엇이 어려운가**
휠체어를 타는 가족, 유모차를 끄는 부모, 오래 걷기 힘든 어르신, 임신 중인 가족과 제주 나들이를 준비하는 사람은 "거기 가도 되나?"를 미리 알기 어렵다. 일반 지도와 여행 앱은 경사·턱·계단·장애인 화장실을 알려 주지 않는다.

**데이터는 있는데 쓰기 어렵다**
제주데이터허브에는 제주특별자치도가 현장 조사한 무장애여행 데이터가 있다. 70개 장소, 1,480개 지점에 "오르막 시작 6도", "단차 9cm", "계단 8개, 휠체어 진입 어려움" 같은 정보가 적혀 있다. 하지만 장소마다 다른 파일에 자유 문장으로 흩어져 있어 장소끼리 비교할 수 없다. 조사 시점도 2021년이라, 함께 적힌 주변 식당이 지금도 영업하는지 알 수 없다.

**목표**
1. 자유 문장을 비교 가능한 표로 바꾼다(규칙 기반, 재현 가능).
2. 사용자가 평소 말투로 말하면 Agent가 조건을 해석해 맞는 장소를 고른다. 이때 **근거 지점과 데이터 기준일을 함께** 보여 준다.
3. 오래된 정보는 최신 데이터(2025 음식점·상가, 허브 약국 API)로 다시 확인한다. 비상시 필요한 약국·응급실·화장실·정류소도 함께 준다.
4. 확인되지 않은 것은 "확인 안 됨"이라고 솔직히 말하고, 전화로 물어볼 질문을 대신 만들어 준다.

## 2. Agent 구조

```
사용자: "아빠가 휠체어 타시는데 주말에 바다 보러 갈 만한 데 있어?"
   │
   ▼
① 코드가 먼저 읽음 (app/agent.py)
   이동 유형 단서(휠체어→manual_wheelchair), 동네·가게·장소 이름, 날짜·날씨 단어 감지
   단서가 전혀 없는 짧은 질문이면 버튼으로 한 번만 되묻기
   │
   ▼
② OpenAI gpt-5.4-mini 함수 호출 반복 (최대 6회)
   모델이 도구를 골라 부르고, 결과를 보고 다음 행동을 정함
   ┌────────────────────────────────────────────────────────────┐
   │ recommend_places   조건 맞는 장소 247곳 중 후보 + 판정·근거      │
   │ get_place_detail   코스 지점·주의 지점·가까운 화장실·정류소       │
   │ find_nearby_help   약국(폐업 제외)·병의원·응급실·화장실·정류소   │
   │ search_food        근처 식당·카페(층·휠체어 진입·식사 조건)      │
   │ get_weather        날짜별 비·바람 예보와 주의                   │
   │ plan_outing        장소→식당→카페 반나절 일정 + 일정표          │
   │ ask_user           부족한 조건을 버튼으로 되묻기                │
   └────────────────────────────────────────────────────────────┘
   │
   ▼
③ 코드가 보정
   모델이 빠뜨린 동네(시작 화면에서 고른 지역 포함)·이용자 유형·이미 본 장소·1층 우선 조건을 채움
   장소 후보는 최소 3곳을 받아 비교할 수 있게 함
   사용자가 말하지 않은 식사 조건은 지움(지어내기 방지)
   │
   ▼
④ 짧은 답(형식 고정, 최대 4줄) + 지도·대시보드 카드(근거 원문·기준일·출처)
```

**역할 나눔.** AI는 말을 해석하고 도구를 고르고 쉬운 말로 설명한다. 장소 선별, 경사 단계, 판정, 거리 계산, 영업 대조는 **코드가 계산**한다. 그래서 같은 입력에는 같은 후보가 나온다. 판정 근거가 된 원문은 AI에게 넘기지 않고 화면에 그대로 보여 준다.

**하지 않는 것.** 예약·결제·전화 같은 외부 행동, "안전하다"는 보장, 데이터에 없는 시설 추측, 맛 순위, 의학적 판단은 하지 않는다.

**AI가 없을 때.** OpenAI 키가 없거나 연결이 끊기면 버튼·단어 기반 **기본 모드**로 바뀐다. 기본 모드도 저장된 데이터로 장소를 추천한다.

## 3. 주요 기능

| 기능 | 설명 | 근거 데이터 |
|---|---|---|
| 이용자 유형 4가지 | 휠체어 / 유모차 / 걷기 힘든 어르신 / 임신 중. 처음 화면 단추나 말("할머니 모시고")로 정함 | 무장애 일반정보의 유형별 추천 여부 |
| 나들이 장소 추천 | 247곳 중 동네·분위기(바다·숲·마을·실내 등)·화장실·시간 조건으로 고르고, 판정(갈 만해요 / 동행인 도움이 있으면 갈 만해요 / 확인이 더 필요해요)과 이유, 조심할 점, 비 오면 대신 갈 곳을 줌 | 무장애 위치정보(경사·턱·계단), 관광공사 무장애 정보 |
| 판정 근거 보기 | 판정을 누르면 근거가 된 조사 지점 원문과 기준일이 보임 | 위치정보 원문 |
| 코스 지도 | 코스 지점을 지도에 그리고 주의 지점은 빨강, 화장실 표시. 현장 사진(50곳) 크게 보기 | 위치정보, 일반정보 사진 |
| 근처 식당·카페 | 1층 우선, 휠체어 진입 확인 가게 표시, 식사 조건 7가지(씹기 편한, 속 편한, 안 매운, 해산물 없는, 싱거운, 아이 메뉴, 날음식 피하기) | 상가 정보, 음식점 목록(층), 2021 주변시설 + 영업 대조 |
| 병원·약국·화장실 | 가까운 약국(폐업 제외)·병의원·응급실은 '병원·약국' 탭, 장애인 화장실은 '코스' 탭, 가장 가까운 버스 정류소는 '한눈에' 탭에 보여 줌. 모두 직선거리, 전화 단추 | 상가 정보, 응급실, 허브 약국 API, 공중화장실, 허브 정류소 API |
| 날씨 | 날짜별 비·바람 예보와 이동 유형별 주의 | Open-Meteo |
| 반나절 일정 | 장소 → 식당 → (원하면) 카페. 답 아래 '일정표 내려받기'로 인쇄·저장용 한 장짜리 일정표(확인표, 급할 때 연락처 포함) | 위 도구 결과 |
| 내 일정 | 추천 장소·식당 카드의 '+ 일정'으로 10곳까지 담고, 순서를 바꿔 '일정표 내려받기'로 같은 모양의 한 장짜리 일정표를 받음. 지도에 들르는 순서 번호. 로그인 없이 이 브라우저에만 저장 | 위 도구 결과 |
| 전화로 확인할 것 | 데이터로 확인 안 된 것을 답의 '확인할 점'과 일정표의 질문 목록으로 안내 | 이동 유형·식사 조건 |
| 내 위치·공항·항구 기준 | "내 근처", "공항에서 가까운" 같은 기준 위치. 알아듣는 기준점은 제주공항, 제주항 여객터미널, 서귀포항, 성산항, 중문관광단지, 제주시청, 서귀포시청. 그 밖에 나들이 장소·동네·가게 이름도 기준이 됨 | 브라우저 위치(동의 시), 장소·상가 정보 |
| 지역 고르기 | 시작 화면에서 상관없어요 / 제주시내 / 애월·한림 / 중문·서귀포 / 성산·구좌 중 고르면 그 지역 안에서만 장소·식당을 찾음(이어지는 대화도). 지역은 비짓제주 구분 | 제주관광공사 비짓제주 지역 구분 |
| 화면 | 섬 전체를 볼 때 '애월 16곳'처럼 지역마다 이름과 곳 수 이름표(초록·주황 번갈아, 누르면 다가감), 지도 왼쪽 '내 위치' 단추. 추천 1순위는 지도·목록·대화에서 같은 곳으로 보여 줌. 코스 선은 실제 길 모양(OpenStreetMap 도보 길찾기로 미리 맞춤, 구간의 71%)을 따르고 길을 못 찾은 구간만 점선. 대화 입력칸은 긴 글을 다음 줄로 이어 5줄까지 늘어남(`Enter` 보내기, `Shift+Enter` 줄바꿈) | — |
| 큰 글씨 | 어르신을 위한 글씨 크게 보기 | — |

## 4. 실행 결과

아래는 실제 실행 결과다(모델 gpt-5.4-mini, 2026-11-20 00:34 시나리오 테스트 기록 `docs/scenario_results.json`). 답변은 기록에 남은 글을 그대로 옮겼다.

**휠체어 + 바다** — "아빠가 휠체어 타시는데 주말에 바다 보러 갈 만한 데 있어?"
도구: `get_weather → recommend_places`
> **종달항과해안길** — 갈 만해요
> 기록된 경사가 완만한 편이고 장애인 화장실·주차장이 있어 아빠와 함께 바다 보러 가기 좋아요.
> 조심할 점: 턱 정보와 쉬어 갈 곳 기록은 없어서 가기 전에 확인해 보세요.
> 비 오면: 해녀박물관

**유모차 + 동네** — "유모차 끌고 애월 쪽 산책하고 싶어"
도구: `recommend_places`
> **제주불빛정원** — 갈 만해요
> 출입구까지 턱이 없어 유모차도 들어갈 수 있고, 넓은 화장실도 있어요.
> 조심할 점: 유모차 대여는 가능하지만, 다른 편의시설은 확인이 안 된 항목이 있어요.
> 비 오면: 테디베어하우스 테지움

**날씨 판단** — "내일 바람 많이 불면 휠체어로 해안길 가도 괜찮을까?"
도구: `get_weather → recommend_places` (내일 예보 바람 10.57m/s를 보고 장소를 고름)
> **종달항과해안길** — 갈 만해요
> 기록된 경사가 완만한 편이고 장애인 화장실과 주차장이 있어 수동 휠체어도 비교적 맞아요.
> 조심할 점: 쉬어 갈 곳 기록은 없어서 바람이 강하면 더 힘들 수 있어요, 가기 전에 전화로 확인해 보세요.
> 비 오면: 해녀박물관

**식사 불편(사용자 체험 중 발견한 질문)** — "이번에 제주도 왔는데 제주시로 왔어. 근데 할머니가 이가 안좋으셔서 마땅히 갈 식당이 없는데 어디갈까?"
도구: `search_food` (조건: 씹기 편한 음식)
> **88국밥** — 국/탕/찌개류 · 1층
> 씹기 편한 국밥이라 할머니처럼 이가 안 좋으실 때 부담이 덜한 편이에요.
> 확인할 점: 입구 정보가 없어서, 가기 전에 전화로 1층 진입과 자리 이동이 편한지 확인해 보세요.
> 확인할 점: 죽이나 부드러운 메뉴가 있나요?

답변 아래에는 추천 후보 단추와 가게마다 `길안내`·`전화`·`지도` 단추가 붙는다. 판정 근거 원문과 기준일은 답변 아래가 아니라 오른쪽 패널(휴대폰은 아래 시트)에 나온다.

## 5. 검증 방법과 결과

| 검증 | 방법 | 결과 |
|---|---|---|
| 지점 설명 추출 정확도 | 무작위 표본을 원문과 대조, 회차마다 새 표본 (`docs/추출_검수기록.md`) | 2021 조사: 95.0% → 93.3% → 96.7% (60개씩 3회) · 2020 조사: 87.5% → 97.5% (40개씩 2회) |
| 튜닝·회귀 시나리오 | 19개 질문, `scripts/04_scenario_test.py` | **19/19** |
| 확인용 시나리오 | 튜닝에 쓰지 않은 8개, `scripts/05_holdout_test.py` | 처음 실행 **5/8** → 고친 뒤 8/8 |
| 폭넓은 질문 | 46개(범위 밖 질문·형식 점검 포함), `scripts/07_broad_test.py` | **46/46** |
| API 서버 | `server/test_api.py` (pytest) | 31개 모두 통과 |

**자동 채점 기준**: 튜닝·회귀·확인용 시나리오는 ① 사용자 조건(이동 유형·동네·식사 조건)을 지켰나, ② **답변의 장소·가게 이름이 모두 도구 결과에 있나**(지어내기 점검) 두 가지가 모두 맞아야 통과다. 부른 도구는 기록하고, 일부 질문의 조건 검사 안에서만 쓴다. 폭넓은 질문은 여기에 필요한 도구, 답변 형식, 금지 표현("안전합니다" 같은 보장)까지 본다.

**정직하게 볼 점.** 세 세트(시나리오 19, 확인용 8, 폭넓은 질문 46) 모두 튜닝 중에 보며 고쳤으므로 점수가 높게 나올 수 있다. 일부 질문은 채점이 느슨하다(예: 숲길 질문 7번은 코스 자료가 없는 곳도 통과, 8·10번은 도구를 불렀는지만 봄. `docs/테스트_기록.md` 4장). 처음 보는 질문에서의 성능은 확인용 첫 실행 결과 5/8이 더 정확하다. 이때 드러난 약점(낯선 이동 유형 단어, 장소 이름 일부로 찾기)은 고쳤다. 모델 응답은 실행마다 조금씩 다를 수 있다.

## 6. 한계

- 무장애 현장 정보는 2020~2021년 조사 자료라 지금 시설 상태와 다를 수 있다. 화면에 기준일을 표시하고 방문 전 확인을 권한다.
- 관광공사 장소 177곳은 시설 입구·편의시설 기준 자료다. 코스를 따라 경사를 잰 자료가 아니다.
- 법정 접근로 기준으로는 경사 기록이 있는 54곳 중 53곳이 기준을 넘는다. 그래서 장소끼리 비교하는 상대 단계를 쓴다. 상대 단계는 "갈 수 있다"는 보장이 아니다.
- 병원·약국·정류소 거리는 직선거리다. 휠체어 기준 길찾기는 지도 서비스가 제공하지 않는다. 저상버스 운행 여부는 확인하지 않는다.
- 식당 메뉴, 좌식·입식 여부, 엘리베이터 자료가 없다. 식사 조건은 업종·가게 이름으로 추정하고 "추정"이라고 표시한다.
- 주변시설의 빈칸이 "불가"인지 "미조사"인지 구분할 수 없어 "확인 안 됨"으로 보여 준다. 상호가 바뀐 가게는 영업 대조에서 놓칠 수 있다.
- 실제 이동약자 사용자를 대상으로 한 테스트는 이번 범위에 들지 않았다.

## 7. 제주빅데이터센터 활용 방안

**센터 PC에서 바로 실행.** 센터 Agent 운영 PC(i7-8700 / GTX 1060 / RAM 32GB)에서 돌아가도록 만들었다. AI 연산은 외부 API가 처리하므로 GPU 부담이 없다. Python 3.11 이상과 Node.js 20 이상만 있으면 된다. 데이터는 CSV로 저장해 두었기 때문에 실행 중에는 허브 API 키가 필요 없다. OpenAI 키가 없어도 기본 모드로 장소 추천이 된다.

**도민 상담 창구.** 센터를 찾은 도민이나 복지·관광 담당자가 "휠체어 타는 어머니와 갈 곳"을 물으면, 근거 원문과 기준일이 붙은 결과를 보여 주고 일정표를 인쇄해 줄 수 있다.

**데이터 갱신 흐름.** 새 조사 자료나 최신 음식점·약국 데이터가 허브에 올라오면 `scripts/01~07`을 다시 돌리면 된다. 앞 단계 결과를 뒤 단계가 읽으므로 번호 순서가 아니라 정해진 순서(01 → 02 → 06 → 03 → 06 contacts → 06_place_photos·07_hub_api, `docs/데이터_활용_명세.md` 4장)로 돌린다. 표와 판정이 자동으로 다시 만들어진다(README 7장). 추출 규칙은 코드로 공개되어 있어 결과를 재현하고 검수할 수 있다.

**확장.** 같은 구조(자유 문장 → 규칙 기반 표 → 도구 → Agent)를 센터가 보유한 다른 현장 조사 데이터에도 쓸 수 있다. 향후 과제는 다음과 같다.
- 저상버스 실시간 도착, 휠체어 대여 수량 연결
- 이용자 제보로 오래된 무장애 정보 갱신
- 센터 현장 조사로 식당 입식 테이블·엘리베이터 정보 보강

## 8. 사용 AI와 외부 서비스

- 서비스 안: OpenAI gpt-5.4-mini(함수 호출). 데이터 정제에는 AI를 쓰지 않았다.
- 개발 과정: Claude Code(Anthropic Claude)를 코드 작성·수정, 테스트 스크립트, 문서 초안, 추출 검수 1차 대조에 썼다. 기획, 데이터 선택, 검토와 최종 판단은 팀이 했다.
- 외부 API: 한국관광공사 무장애 여행 정보, 카카오 로컬 API·카카오맵, Open-Meteo. 전체 목록과 오픈소스 라이선스는 `docs/데이터_활용_명세.md` 2·6장에 있다.
